☁️ 1. Cloud Computing (Computação em Nuvem) ▼
📦 Modelos de Serviço
🧠 Mnemônico – SPI
S – P – I
SaaS (Software) · PaaS (Plataforma) · IaaS (Infraestrutura)
IaaS – Infraestrutura
O mais básico. Hardware (computação/armazenamento). Cliente gerencia SO, middleware e apps.
PaaS – Plataforma
Ambiente para desenvolvimento. Sem gerenciar infraestrutura física.
SaaS – Software
Software completo via web. Ex: Office 365, Gmail.
🏗️ Modelos de Implantação (NIST SP 800-145)
  • Pública: Aberta ao público geral; infraestrutura do provedor.
  • Privada: Uso exclusivo de uma organização. Pode ser gerenciada por terceiros (não é obrigatoriamente interna).
  • Híbrida: Combinação de duas ou mais nuvens que permanecem entidades únicas.
  • Comunitária: Compartilhada por organizações com interesses em comum (ex: conformidade).
⚡ Características Essenciais
  • Elasticidade Rápida: Recursos providos rapidamente (percepção de "ilimitado").
  • Escalabilidade Automática: Recursos ajustados dinamicamente conforme demanda.
  • Mensuração de Serviço: Pagamento por uso (on-demand).
  • Resource Pooling: Modelo multiusuário (multi-tenant).
📌 Exemplo Prático
A Câmara dos Deputados contrata a AWS para hospedar servidores virtuais (EC2) — isso é IaaS.
Um desenvolvedor usa o Google App Engine para criar uma aplicação sem se preocupar com servidores — isso é PaaS.
Um servidor público acessa o Gmail pelo navegador — isso é SaaS.
Se a Câmara usa nuvem própria (privada) e AWS (pública) juntas → Nuvem Híbrida.
📝 Questões para Fixar
Q1. Na computação em nuvem, o modelo IaaS fornece ao cliente o controle total sobre o sistema operacional, middleware e aplicações, sendo responsável apenas pela infraestrutura física.
✅ CERTO ❌ ERRADO
✅ CERTO. No IaaS, o provedor fornece hardware (servidores, armazenamento, rede) e o cliente gerencia SO, middleware e aplicações.
Q2. A nuvem privada é, por definição, uma infraestrutura implantada nas instalações internas da organização, não podendo ser gerenciada por terceiros.
✅ CERTO ❌ ERRADO
❌ ERRADO. A nuvem privada é de uso exclusivo, mas pode sim ser gerenciada por terceiros e estar fora das instalações da organização (NIST SP 800-145).
⛏️ 2. Ciência de Dados e Mineração (CRISP-DM) ▼
🔄 6 Fases do CRISP-DM

📊 Tarefas de Mineração
Associação
Regras "Se X, então Y" (cesta de compras). Indicadores: Suporte e Confiança.
Clustering (Agrupamento)
Técnica não supervisionada. K-means agrupa por similaridade.
Classificação
Supervisionada (rótulos predefinidos). Ex: Naive Bayes, Árvores de Decisão.
Regressão
Previsão de valores contínuos. Objetiva predição e estimação.
📌 Exemplo Prático – Mineração em Supermercado
Associação: "Clientes que compram fraldas também compram cerveja" → Regra com Suporte = 5% e Confiança = 70%.
Clustering: Agrupar clientes por perfil de compra sem rótulos prévios (jovens, famílias, idosos).
Classificação: Prever se um e-mail é spam ou não (rótulo binário: spam/não-spam).
Regressão: Prever o valor de vendas do próximo trimestre (valor contínuo em R$).
📝 Questões para Fixar
Q1. Na metodologia CRISP-DM, a fase de Data Understanding inclui a construção de modelos preditivos para avaliar a qualidade dos dados coletados.
✅ CERTO ❌ ERRADO
❌ ERRADO. A fase de Data Understanding envolve coleta, descrição e exploração inicial. A construção de modelos preditivos ocorre na fase de Modeling.
Q2. A clusterização é uma técnica de aprendizado supervisionado que agrupa dados com base em rótulos pré-definidos.
✅ CERTO ❌ ERRADO
❌ ERRADO. A clusterização é não supervisionada — agrupa dados por similaridade sem rótulos pré-definidos. Quem usa rótulos é a Classificação (supervisionada).
🔄 3. Engenharia de Dados: ETL vs ELT ▼
ETL
Extract → Transform → Load
Transformação antes da carga
Staging Area
Dados estruturados
ELT
Extract → Load → Transform
Transformação dentro do destino
Big Data (semi/não estruturados)
Menor custo de manutenção
🔧 Técnicas Importantes
  • Extração Incremental: Extrai apenas o que mudou (mais eficiente que Full).
  • Derivação: Cria novos atributos via cálculos (não é apenas vincular fontes).
  • Limpeza: Reorganização para qualidade e consistência. Remove dados incorretos, não dados "corretos".
  • Junção: Vincula dados de diferentes fontes (não confunda com derivação).

📌 Exemplo Prático – ETL vs ELT
ETL: A Câmara extrai dados de sistemas legados (RH, financeiro), transforma na Staging Area (padroniza CPFs, corrige datas), e depois carrega no Data Warehouse.
ELT: Uma empresa de e-commerce despeja logs brutos de navegação direto no Data Lake (AWS S3) e depois transforma com Spark/BigQuery dentro do próprio destino.
📝 Questões para Fixar
Q1. No processo ELT, a transformação dos dados ocorre em uma área temporária (Staging Area) antes de serem carregados no repositório de destino.
✅ CERTO ❌ ERRADO
❌ ERRADO. Isso descreve o ETL. No ELT, os dados são carregados primeiro e a transformação ocorre dentro do destino.
Q2. A limpeza de dados no processo ETL tem como objetivo remover dados incorretos, duplicados ou mal formatados, e não dados considerados corretos.
✅ CERTO ❌ ERRADO
✅ CERTO. A limpeza corrige ou remove dados incorretos, duplicados ou inconsistentes. Dados corretos são mantidos.
🗄️ 4. Bancos de Dados Relacionais ▼
📋 Conceitos Fundamentais
  • Estrutura: Tabelas (Relações), Linhas (Tuplas/Registros), Colunas (Atributos/Campos).
  • Chave Primária (PK): Valor único e obrigatório. Pode ser composta.
  • Integridade Referencial: FK deve corresponder a uma PK existente ou ser nula.
  • Independência Física: Mudanças na estrutura física não afetam a lógica.
  • Cardinalidade: 1:1, 1:N, N:N. Relacionamentos N:N viram tabelas associativas.
📊 Normalização
Forma NormalRequisito PrincipalO que elimina?
1FNAtributos atômicosAtributos multivalorados e compostos
2FN1FN + Dependência Funcional TotalDependências parciais (chaves compostas)
3FN2FN + Sem dep. transitivasAtributos dependem de não-chave
4FN3FN (ou BCNF)Dependências multivaloradas independentes
💡 Uma tabela na 3FN está obrigatoriamente na 1FN e 2FN. Normalização excessiva pode prejudicar desempenho (excesso de joins).
💾 Recuperação em SGBD
  • COMMIT: Torna as alterações permanentes.
  • ROLLBACK: Desfaz transações não confirmadas (garante atomicidade).
  • LOG: Registro para recuperação; deve ser armazenado separado dos dados.
📁 Dados Estruturados vs Não Estruturados
Dados Estruturados
Organizados em tabelas com linhas e colunas
Esquema fixo e predefinido
SQL para consulta
Ex: BD relacional, planilhas
Dados Não Estruturados
Sem esquema fixo
Texto livre, imagens, vídeos, áudios
Armazenados em Data Lakes, NoSQL
Ex: e-mails, PDFs, redes sociais
  • Semiestruturados: Possuem marcações/tags mas sem esquema rígido. Ex: JSON, XML, CSV.
  • NoSQL: Bancos para dados não estruturados/semiestruturados. Tipos: documento (MongoDB), chave-valor (Redis), colunar (Cassandra), grafo (Neo4j).
  • ACID vs BASE: Relacional = ACID (consistência forte). NoSQL = BASE (consistência eventual, alta disponibilidade).
🔗 Modelagem Entidade-Relacionamento
  • N:N: Sempre resulta em uma terceira tabela (associação/ligação).
  • 1:1: Pode ser na mesma tabela ou em tabelas separadas com FK.
  • Engenharia Reversa: Obter modelo conceitual a partir do BD existente.
  • Especialização: Decompor entidade geral em específicas (ex: Pessoa → Física e Jurídica).
📌 Exemplo – Normalização Passo a Passo
Tabela original: Aluno(Matrícula, Nome, Telefones, CursoCod, CursoNome)
1FN: Remover "Telefones" multivalorado → criar tabela AlunoTelefone(Matrícula, Telefone).
2FN: Se PK = (Matrícula, CursoCod) e CursoNome depende só de CursoCod → mover CursoNome para tabela Curso.
3FN: Se CursoNome depende de CursoCod (não-chave) → eliminar dependência transitiva separando Curso(CursoCod, CursoNome).
📝 Questões para Fixar
Q1. Em um banco de dados relacional, a integridade referencial garante que uma chave estrangeira sempre corresponda a um valor existente na chave primária da tabela referenciada ou seja nula.
✅ CERTO ❌ ERRADO
✅ CERTO. A FK deve corresponder a uma PK existente ou ser nula. Essa é a definição exata de integridade referencial.
Q2. Uma tabela que se encontra na segunda forma normal (2FN) está, necessariamente, na primeira forma normal (1FN), mas pode conter dependências transitivas.
✅ CERTO ❌ ERRADO
✅ CERTO. A 2FN exige estar na 1FN + sem dependências parciais. Dependências transitivas são eliminadas apenas na 3FN.

📝 Questões para Fixar
Q1. A análise preditiva responde à pergunta "o que devo fazer?" e apresenta simulações e respostas ideais para a tomada de decisão.
✅ CERTO ❌ ERRADO
❌ ERRADO. "O que devo fazer?" é a análise prescritiva. A análise preditiva responde "o que vai acontecer?" usando modelos e dados históricos.
🤖 6. Inteligência Artificial e Machine Learning ▼
🧠 Conceitos Gerais
IA Generativa
Cria conteúdos novos (texto, imagem, áudio). Baseada em Transformers (GPT). Probabilidade conjunta p(x,y).
IA Discriminativa
Classifica ou rotula dados existentes. Ex: É spam ou não?
RAG
Retrieval Augmented Generation. Recupera dados externos para enriquecer o prompt e reduzir "alucinações".
📐 Algoritmos e Técnicas
Supervisionado
Dados rotulados
Classificação e Regressão
Naive Bayes, Árvores de Decisão
Não Supervisionado
Dados sem rótulos
Clustering (K-means)
PCA (redução de dimensionalidade)
⚠️ Acurácia é ruim para classes desbalanceadas. Prefira a curva ROC/AUC (quanto mais perto do canto superior esquerdo, melhor).
💬 PLN (Processamento de Linguagem Natural)
  • Tokenização: Segmentação do texto em tokens (unidades menores).
  • Stemming: Corta a palavra até o radical (pode gerar palavras sem sentido).
  • Lemmatização: Reduz à forma canônica (dicionário). Exige análise gramatical (POS Tagging).
  • Bag of Words (BoW): Vetoriza pela frequência, mas ignora ordem e contexto.
  • Auto-atenção (Transformers): Foca em partes diferentes da frase para entender contexto de longo alcance.
📊 Mineração de Dados
  • Conceito: Processo de descobrir padrões, correlações e anomalias em grandes volumes de dados usando técnicas estatísticas e de ML.
  • KDD (Knowledge Discovery in Databases): Processo completo: Seleção → Pré-processamento → Transformação → Mineração → Interpretação.
  • Tarefas: Classificação, Regressão, Clustering, Associação (regras como "quem compra X também compra Y"), Detecção de Anomalias.
  • Regras de Associação: Suporte = frequência do padrão. Confiança = probabilidade condicional. Lift > 1 indica associação positiva.
  • Diferença: Mineração ≠ consulta SQL. Mineração descobre padrões desconhecidos; SQL recupera dados conhecidos.
🗄️ Big Data: Conceito e 5 V's
  • Conceito: Conjuntos de dados tão grandes e complexos que ferramentas tradicionais não conseguem processar eficientemente.
  • Volume: Terabytes, Petabytes de dados.
  • Velocidade: Dados gerados e processados em tempo real ou quase real (streaming).
  • Variedade: Dados estruturados, semiestruturados e não estruturados (textos, imagens, vídeos, sensores).
  • Veracidade: Qualidade e confiabilidade dos dados (podem conter ruído, inconsistências).
  • Valor: Capacidade de extrair informação útil e insights dos dados para tomada de decisão.
💡 Tecnologias: Hadoop (MapReduce, HDFS), Spark (processamento em memória), Data Lakes, NoSQL.
🤖 IA Generativa: Características
  • Definição: Modelos de IA que criam conteúdo novo (texto, imagem, código, áudio, vídeo) a partir de padrões aprendidos.
  • Base: Arquitetura Transformer (2017, Google). Mecanismo de auto-atenção para entender contexto.
  • LLMs: Large Language Models — treinados em bilhões de parâmetros sobre vastos corpus de texto.
  • Exemplos: GPT (OpenAI), Gemini (Google), Claude (Anthropic), LLaMA (Meta).
  • Alucinações: Modelo gera informação plausível mas incorreta. RAG e grounding ajudam a mitigar.
  • Prompt Engineering: Técnica de formular instruções claras para obter melhores respostas do modelo.
  • Fine-tuning: Ajuste fino do modelo pré-treinado para domínio específico (ex: jurídico, médico).
  • Riscos: Viés algorítmico, deepfakes, desinformação, questões de propriedade intelectual.
💡 Ética no Serviço Público: Foco em transparência, combate ao viés algorítmico e responsabilidade digital (LGPD).
📌 Exemplo – Stemming vs Lemmatização
Palavra: "correndo"
Stemming: "corr" (radical bruto — pode não existir no dicionário).
Lemmatização: "correr" (forma canônica correta do verbo).

Palavra: "melhores"
Stemming: "melhor" (ok neste caso).
Lemmatização: "bom" (forma canônica do adjetivo no dicionário).
📝 Questões para Fixar
Q1. A técnica RAG (Retrieval Augmented Generation) tem como objetivo principal substituir o modelo de linguagem por uma base de dados externa para eliminar completamente as alucinações.
✅ CERTO ❌ ERRADO
❌ ERRADO. O RAG não substitui o modelo — ele o complementa recuperando dados externos para reduzir (não eliminar) alucinações.
Q2. A IA generativa cria novos conteúdos (texto, imagem, áudio), enquanto a IA discriminativa classifica ou rotula dados existentes.
✅ CERTO ❌ ERRADO
✅ CERTO. Generativa = cria novos conteúdos (GPT, DALL-E). Discriminativa = classifica dados existentes (spam ou não-spam).

👤 Responsabilidades dos Usuários de TI
  • Senhas: Não compartilhar, não anotar em local visível, trocar periodicamente. Usar senhas fortes (mín. 12 caracteres, maiúsculas, minúsculas, números, símbolos).
  • Bloqueio de tela: Bloquear o computador ao se ausentar (Win + L).
  • Software autorizado: Não instalar programas sem autorização da equipe de TI.
  • E-mails suspeitos: Não abrir anexos ou clicar em links de remetentes desconhecidos.
  • Dados sensíveis: Classificar e proteger conforme política institucional. Não enviar dados sigilosos por canais não autorizados.
  • Incidentes: Reportar imediatamente qualquer incidente de segurança à equipe responsável.
🎣 Engenharia Social: Phishing, Vishing e Métodos
  • Phishing: Fraude via páginas/emails falsos. NÃO é interceptação (isso é Man-in-the-Middle). Canal: e-mail.
  • Spear Phishing: Alvo específico (ex: TI da empresa). Personalizado com dados da vítima.
  • Whaling: Alvo de alto escalão (CEOs/CFOs). Engenharia social sofisticada.
  • Vishing: Phishing por voz/telefone. Criminoso se passa por banco, suporte técnico ou órgão público.
  • Smishing: Phishing por SMS. Links maliciosos via mensagens de texto.
  • Pharming: Envenenamento de DNS / redirecionamento de tráfego legítimo para site falso.
  • Pretexting: Criar uma história/pretexto falso para obter informações (ex: fingir ser do RH).
  • Tailgating: Seguir pessoa autorizada para entrar em área restrita fisicamente.
⚠️ Engenharia Social explora o fator HUMANO, não falhas técnicas. A melhor defesa é treinamento e conscientização.
🛡️ Aplicativos de Segurança
Antivírus
Detecta por assinatura (conhecidos) e heurística (desconhecidos). Falha contra Zero-Day apenas por assinatura.
EDR (Endpoint Detection and Response)
Vai além do antivírus: monitora comportamento em tempo real, detecta ameaças avançadas, permite resposta e investigação remota.
Anti-spyware
Especializado em detectar e remover spyware, adware e keyloggers. Pode ser integrado ao antivírus.
Gerenciador de Senhas
Armazena senhas em cofre criptografado. Uma senha mestra desbloqueia todas. Gera senhas aleatórias fortes.
🔐 Assinatura e Certificação Digital
  • Assinatura Digital: Usa criptografia assimétrica (chave privada do remetente assina, chave pública verifica). Garante: autenticidade, integridade e não repúdio.
  • NÃO garante: Confidencialidade (para isso, criptografa-se com a chave pública do destinatário).
  • Certificado Digital: Documento eletrônico emitido por Autoridade Certificadora (AC) que vincula chave pública à identidade do titular.
  • ICP-Brasil: Infraestrutura de Chaves Públicas Brasileira. AC-Raiz = ITI (Instituto Nacional de Tecnologia da Informação).
  • Tipo A1: Armazenado em software (arquivo). Validade: 1 ano.
  • Tipo A3: Armazenado em hardware (token/smart card). Validade: até 5 anos. Mais seguro.
  • Hash: Função que gera resumo de tamanho fixo. Usada para verificar integridade. Ex: SHA-256.
💡 Processo: Remetente calcula o hash do documento → criptografa o hash com sua chave privada (assinatura) → destinatário descriptografa com a chave pública e compara os hashes.
💾 Backup
Completo (Full)
Cópia de todos os dados. Demorado, restauração rápida (1 mídia).
Incremental
Alterado desde o último backup (qualquer tipo). Rápido p/ gravar, lento p/ restaurar.
Diferencial
Alterado desde o último backup completo. Equilíbrio entre espaço e velocidade.
🧠 Regra 3-2-1
3 – 2 – 1
3 cópias · 2 mídias diferentes · 1 cópia fora do site (remota)
🔍 Antivírus
  • Heurística: Identifica vírus desconhecidos por comportamento. Pode gerar falsos positivos.
  • Assinatura: Identifica vírus conhecidos em lista. Menos eficaz contra Zero-Day.
  • Antivírus ≠ Firewall: Antivírus detecta/remove arquivos; firewall controla tráfego na rede.
📌 Exemplo – Cenário de Ataque
Cenário: Um servidor da Câmara recebe um e-mail com anexo "Edital_Final.pdf.exe". Ao abrir:
1. O arquivo é um Trojan (parece PDF, mas é executável malicioso).
2. O Trojan instala um Backdoor (RAT) no computador.
3. O invasor usa o backdoor para instalar um Ransomware, criptografando os arquivos.
4. Exige pagamento em Bitcoin para liberar os dados.
Defesa: Backup 3-2-1 + treinamento contra Phishing + antivírus com heurística.
📝 Questões para Fixar
Q1. Diferentemente do vírus, o worm é capaz de se propagar automaticamente pela rede, explorando vulnerabilidades, sem necessidade de ação humana.
✅ CERTO ❌ ERRADO
✅ CERTO. O vírus precisa de ação humana (executar o arquivo). O worm é auto-propagável pela rede.
Q2. No backup incremental, são copiados todos os dados que foram alterados desde o último backup completo (full).
✅ CERTO ❌ ERRADO
❌ ERRADO. Isso descreve o backup diferencial. O incremental copia o que mudou desde o último backup de qualquer tipo (full, incremental ou diferencial).
🪟 8. Sistemas Operacionais: Windows, Android e iOS ▼
  • Microsoft Defender: Antivírus/Antimalware integrado.
  • SmartScreen: Verifica phishing e arquivos maliciosos na web.

🤖 Android
  • Base: Kernel Linux. Código-fonte aberto (AOSP). Desenvolvido pelo Google.
  • Loja: Google Play Store. Permite instalação de apps de fontes externas (sideloading) — risco de malware.
  • Permissões: Apps solicitam permissões granulares (câmera, localização, contatos). Usuário pode revogar a qualquer momento.
  • Sandbox: Cada app roda em processo isolado. Um app não acessa dados de outro diretamente.
  • Fragmentação: Múltiplos fabricantes → versões diferentes do SO → atualizações de segurança podem demorar.
  • Criptografia: Criptografia de disco ativada por padrão desde Android 6.0 (Marshmallow).
  • Google Play Protect: Verificação automática de apps contra malware na Play Store.
🍎 iOS (iPhone/iPad)
  • Base: Derivado do macOS (kernel XNU/Darwin). Código fechado e proprietário da Apple.
  • Loja: App Store exclusiva. Apps passam por revisão rigorosa antes da publicação.
  • Sandbox: Isolamento ainda mais restritivo que Android. Apps não podem acessar o sistema de arquivos livremente.
  • Atualizações: Centralizadas pela Apple → todos os dispositivos compatíveis recebem simultaneamente.
  • Face ID / Touch ID: Autenticação biométrica armazenada no Secure Enclave (chip dedicado, dados nunca saem do dispositivo).
  • iCloud: Sincronização e backup na nuvem. Criptografia de ponta a ponta em dados sensíveis.
  • Sideloading: Historicamente não permitido (sem fontes externas). Mudanças recentes na UE (DMA) podem alterar.

🌍 Navegadores (Chrome, Edge, Firefox)

📌 Exemplo – Proxy Direto vs Reverso
Proxy Direto: Um servidor público da Câmara acessa "youtube.com". O proxy intercepta → verifica se está na lista de sites bloqueados → se permitido, faz a requisição em nome do usuário e armazena em cache para acelerar futuros acessos.
Proxy Reverso: Um cidadão acessa "www.camara.leg.br". O proxy reverso recebe a requisição → decide para qual servidor backend encaminhar (balanceamento de carga) → protege os servidores internos.

Q2. A presença do cadeado (HTTPS) na barra de endereço do navegador indica que a conexão está criptografada, mas não garante que o site é legítimo ou seguro.
✅ CERTO ❌ ERRADO
✅ CERTO. HTTPS garante que a conexão é criptografada, mas sites de phishing também podem usar HTTPS. Não é garantia de legitimidade.
🏛️ 11. Gestão e Governança de TI ▼
📋 Governança vs Gestão
  • Governança de TI: Responsabilidade da alta administração. Alinhamento Estratégico (TI + Negócio). Não é exclusiva de grandes empresas.
  • Governança Digital: Não é só tecnologia; envolve políticas, processos e regulamentos para transparência.
  • Accountability: No setor público = prestação de contas e responsabilidade, não apenas conduta ética.

📊 Governança de Dados (DAMA-DMBOK)
  • CDO (Chief Data Officer): Executivo responsável pela estratégia e qualidade dos dados.
  • Data Steward: Guardião do uso, controle e metadados (atua na área de negócios).
  • Data Profiling: "Fotografia inicial" – analisa estrutura e inconsistências antes da limpeza.
  • Metadados: "Dados sobre dados". Cruciais para integrar fontes distintas.
  • Acurácia: Dados representam corretamente a realidade (≠ falta de duplicatas).
  • Consistência: Dados iguais em sistemas diferentes (≠ representação do mundo real).
📌 Exemplo – Utilidade vs Garantia (ITIL)
Serviço: Sistema de votação eletrônica da Câmara.
Utilidade (o que faz): Permite que deputados votem projetos de lei remotamente — aumenta a capacidade legislativa.
Garantia (como é entregue): O sistema está disponível 99,9% do tempo, com backups diários, criptografia e autenticação por certificado digital.
→ A Utilidade torna o serviço "apto para o propósito"; a Garantia o torna "apto para o uso".
📝 Questões para Fixar
Q1. A governança de TI é uma atividade restrita a grandes empresas que possuem departamentos de tecnologia estruturados.
✅ CERTO ❌ ERRADO
❌ ERRADO. A governança de TI não é exclusiva de grandes empresas. Qualquer organização que utiliza TI pode (e deve) implementar governança.
Q2. No contexto de governança de dados (DAMA-DMBOK), o Data Steward é o responsável estratégico pela política de dados da organização e responde diretamente ao CEO.
✅ CERTO ❌ ERRADO
❌ ERRADO. O Data Steward é o guardião operacional dos dados (controle, uso, metadados) na área de negócios. Quem é o executivo estratégico responsável é o CDO (Chief Data Officer).
🖥️ 12. Arquitetura de Computadores ▼
🏗️ Von Neumann

CPU + Memória + Dispositivos de E/S. Ciclo: Busca → Decodificação → Execução.

  • Memórias: Registradores > Cache > RAM > Disco. RAM é volátil; ROM não.
🔌 Barramentos
  • PCI Express: Serial, ponto a ponto. Canal exclusivo por dispositivo (não compartilha largura de banda).
  • PCI Convencional: Paralelo, obsoleto para laptops.
  • USB: Limite de 5m para cabos passivos. Foco em versatilidade de velocidades.
🔢 Sistemas de Numeração
  • Binário → Hexadecimal: Agrupe de 4 em 4 bits. Ex: 1111₂ = F₁₆; 1001₂ = 9₁₆.
  • Complemento de Dois: Inverter bits e somar 1. Representação de números negativos.
  • 16 bits (Signed): Intervalo de -32.768 a +32.767. Representar 32.768 positivo causa overflow.
  • Capacidade: Com n bits → 2ⁿ números distintos.
📌 Exemplo – Conversão Binário → Hexadecimal
Converter 10110011₂ para hexadecimal:
1. Agrupe de 4 em 4: 1011 | 0011
2. Converta cada grupo: 1011₂ = B₁₆ (8+2+1=11) | 0011₂ = 3₁₆ (2+1=3)
3. Resultado: B3₁₆

Complemento de Dois para -5 em 8 bits:
1. +5 em binário: 00000101
2. Inverte bits: 11111010
3. Soma 1: 11111011 → representação de -5.
📝 Questões para Fixar
Q1. Na hierarquia de memórias de um computador, a memória cache é mais rápida que a RAM, porém possui menor capacidade de armazenamento.
✅ CERTO ❌ ERRADO
✅ CERTO. Hierarquia: Registradores > Cache > RAM > Disco. Quanto mais rápida, menor a capacidade e maior o custo.
Q2. O barramento PCI Express utiliza transmissão paralela e compartilha a largura de banda entre todos os dispositivos conectados.
✅ CERTO ❌ ERRADO
❌ ERRADO. O PCI Express usa transmissão serial, ponto a ponto, com canal exclusivo por dispositivo. Quem é paralelo e compartilhado é o PCI Convencional.
🔬 13. Forense Computacional ▼
🗂️ Recuperação de Arquivos Apagados
  • Exclusão lógica: Ao deletar um arquivo, o SO marca o espaço como disponível, mas os dados permanecem no disco até serem sobrescritos.
  • Lixeira: Arquivo movido para a Lixeira ainda está intacto. Exclusão permanente (Shift+Del) remove a referência na MFT/FAT.
  • File Carving: Técnica que recupera arquivos buscando assinaturas (headers/footers) no disco bruto, sem depender do sistema de arquivos.
  • MFT (Master File Table): Tabela do NTFS que registra metadados de todos os arquivos. Arquivos pequenos podem estar inteiramente dentro da MFT.
  • Slack Space: Espaço não utilizado entre o fim do arquivo e o fim do cluster. Pode conter resíduos de dados anteriores.
  • SSD vs HDD: Em SSDs, o comando TRIM zera blocos liberados → recuperação é muito mais difícil que em HDDs.
⚠️ Importante: Quanto mais o disco é utilizado após a exclusão, menor a chance de recuperação (sobrescrita dos setores).
🔍 Identificação, Isolamento, Preservação e Coleta
EtapaDescriçãoCuidados
1. IdentificaçãoReconhecer e localizar potenciais fontes de evidência digitalDocumentar o estado inicial (fotos, vídeos)
2. IsolamentoImpedir alteração ou destruição das evidênciasNão ligar/desligar equipamentos precipitadamente; isolar da rede
3. PreservaçãoGarantir integridade dos dados coletadosCalcular hash (SHA-256/MD5) antes e depois da cópia
4. ColetaCriar cópia forense (imagem bit a bit) da mídiaUsar bloqueador de escrita (write blocker) para evitar alterações
  • Imagem Forense: Cópia bit a bit (setor a setor) do dispositivo. Formatos: DD (raw), E01 (EnCase), AFF.
  • Write Blocker: Dispositivo (hardware ou software) que permite leitura mas impede escrita na mídia original.
  • Ordem de Volatilidade (RFC 3227): Coletar primeiro os dados mais voláteis: Registradores → Cache → RAM → Disco → Logs remotos → Backup.
  • Memória RAM: Evidência volátil — se desligar o computador, perde-se. Pode conter senhas, processos em execução, conexões ativas.
💡 Princípio de Locard: "Todo contato deixa um vestígio." Aplicado à forense digital: toda interação com um sistema deixa rastros.
⛓️ Cadeia de Custódia
  • Conceito: Registro documentado de todos os passos pelos quais uma evidência passa, desde a coleta até a apresentação em juízo.
  • Objetivo: Garantir autenticidade, integridade e rastreabilidade da prova digital.
  • Registrar: Quem coletou, quando, onde, como, por quê. Cada transferência de posse deve ser documentada.
  • Hash: Calculado no momento da coleta e verificado em cada etapa. Se o hash mudar → evidência comprometida.
  • CPP (Art. 158-A a 158-F): O Código de Processo Penal brasileiro regulamenta a cadeia de custódia. Vestígio deve ser isolado, coletado, acondicionado, transportado e armazenado adequadamente.
  • Quebra da cadeia: Evidência pode ser considerada inadmissível em juízo se a cadeia de custódia for violada.
🧠 Etapas da Cadeia de Custódia (CPP)
R – I – C – A – T – R – D
Reconhecimento · Isolamento · Coleta · Acondicionamento · Transporte · Recebimento · Descarte
📋 Log de Eventos do Windows
  • Event Viewer (Visualizador de Eventos): Ferramenta nativa do Windows para consultar logs. Acesso: eventvwr.msc.
  • Logs do Sistema: Eventos do SO (drivers, serviços, hardware).
  • Logs de Segurança: Tentativas de logon (sucesso/falha), acesso a objetos, alterações de política. Essenciais para forense.
  • Logs de Aplicação: Eventos gerados por aplicativos instalados.

📌 Exemplo – Investigação Forense Completa
Cenário: Suspeita de acesso não autorizado a um computador da Câmara.
1. Identificação: O CSIRT detecta múltiplas falhas de logon (Event ID 4625) seguidas de um logon bem-sucedido (4624) às 3h da manhã.
2. Isolamento: O computador é desconectado da rede (cabo removido). Não é desligado para preservar a RAM.
3. Coleta: Dump da memória RAM (processos, conexões) → Imagem forense do disco com write blocker → Hash SHA-256 calculado.
4. Cadeia de Custódia: Formulário preenchido com data, hora, responsável, hash da imagem, lacre na mídia.
5. Análise: File carving revela arquivo deletado "exfiltrar.ps1". Log de eventos mostra criação de conta (4720) e novo serviço (7045).
6. Resultado: Evidências apresentadas com hashes íntegros, cadeia de custódia documentada.
📝 Questões para Fixar
Q1. Na forense computacional, o file carving é uma técnica que depende do sistema de arquivos (FAT, NTFS) para localizar e recuperar arquivos apagados.
✅ CERTO ❌ ERRADO
❌ ERRADO. O file carving não depende do sistema de arquivos. Ele busca assinaturas (headers/footers) diretamente no disco bruto, independentemente da estrutura de metadados.
Q2. A cadeia de custódia tem como objetivo garantir que a evidência digital não seja alterada desde a coleta até a apresentação em juízo, registrando todos os responsáveis e procedimentos realizados.
✅ CERTO ❌ ERRADO
✅ CERTO. A cadeia de custódia garante autenticidade, integridade e rastreabilidade. Cada transferência de posse deve ser documentada, e o hash deve ser verificado em cada etapa.
Q3. De acordo com a ordem de volatilidade (RFC 3227), os dados armazenados em disco rígido devem ser coletados antes dos dados presentes na memória RAM.
✅ CERTO ❌ ERRADO
❌ ERRADO. A RAM é mais volátil que o disco. Deve-se coletar primeiro os dados mais voláteis: Registradores → Cache → RAM → Disco.
