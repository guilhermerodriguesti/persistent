1. Noções de Sistemas Operacionais
Windows, Android e iOS — conceitos, atalhos e diferenças
Edital §1▶
WindowsMuito cobrado▶

Conceitos Rápidos

  • Multitarefa preemptiva: SO decide quando cada programa usa a CPU (ex.: rodar Word e Chrome ao mesmo tempo)
  • NTFS: sistema de arquivos padrão — suporta permissões, criptografia (EFS), compactação e arquivos >4 GB. FAT32: limite 4 GB por arquivo, sem permissões
  • Gerenciador de Tarefas (Ctrl+Shift+Esc): mostra processos, CPU, memória, disco. Permite "Finalizar tarefa"
  • Registro do Windows (regedit): banco de dados hierárquico com config. do SO e programas. 5 hives: HKLM, HKCU, HKCR, HKU, HKCC
  • Firewall do Windows: filtra tráfego de rede — regras de entrada e saída. Já vem ativado por padrão
  • BitLocker: criptografia de disco inteiro — usa chip TPM. EFS: criptografia de arquivos individuais no NTFS
  • Windows Defender: antivírus nativo. Nas versões recentes inclui proteção contra ransomware (acesso a pastas controlado)
  • UAC (Controle de Conta de Usuário): aviso quando programa tenta alterar configurações do sistema → "Deseja permitir?"

Atalhos essenciais para lembrar

Win+E = Explorador de Arquivos  |  Win+L = Bloquear tela  |  Win+R = Executar  |  Win+I = Configurações

Ctrl+Z = Desfazer  |  Ctrl+Shift+Esc = Gerenciador de Tarefas  |  Alt+Tab = Alternar janelas

Win+D = Área de trabalho  |  Win+Print Screen = Captura de tela salva em Imagens

Cuidado na prova

  • "FAT32 suporta arquivos maiores que 4 GB" — ERRADO, limite é 4 GB (use NTFS ou exFAT)
  • "BitLocker criptografa apenas arquivos" — ERRADO, criptografa disco inteiro; EFS que é por arquivo
  • "Windows Defender substitui completamente antivírus de terceiros" — cuidado, é eficaz mas a banca pode questionar contexto corporativo
Android e iOSCobrado▶

Conceitos Rápidos

  • Android: SO open source (código aberto), baseado em Linux, desenvolvido pelo Google. Permite instalar apps fora da loja (sideloading). Customizável por fabricantes
  • iOS: SO proprietário da Apple, exclusivo para iPhone/iPad. Não permite sideloading (só App Store). Mais restritivo = maior controle de segurança
  • Permissões: ambos pedem autorização para câmera, microfone, localização. No Android pode-se instalar APK externo; no iOS não
  • Sandbox: apps rodam isolados em ambos os SOs — um app não acessa dados de outro diretamente
  • Atualizações: iOS atualiza todos os dispositivos ao mesmo tempo; Android depende de cada fabricante (fragmentação)

Macete para lembrar

🤖 Android = "A de Aberto" (open source, APK, customizável)
🍎 iOS = "i de Isolado" (fechado, só App Store, Apple controla tudo)

Cuidado na prova

  • "Android é mais seguro que iOS por ser open source" — ERRADO, open source não garante mais segurança
  • "iOS permite instalação de apps fora da App Store" — ERRADO (regra geral — exceções recentes na UE não são foco)

2. Navegadores de Internet, Webmail e Ferramentas de Produtividade
Chrome, Firefox, Edge, protocolos de e-mail, Office, Google Workspace
Edital §2▶
Navegadores de InternetMuito cobrado▶

Conceitos Rápidos

  • Chrome (Google), Firefox (Mozilla), Edge (Microsoft, baseado no Chromium): todos suportam extensões/complementos
  • Cookies: pequenos arquivos armazenados pelo site no seu PC para lembrar preferências/login. Cookies de terceiros = rastreamento publicitário
  • Cache: cópia local de páginas/imagens para carregamento mais rápido. Limpar cache = Ctrl+Shift+Del
  • Navegação privativa: Ctrl+Shift+N (Chrome/Edge) ou Ctrl+Shift+P (Firefox). NÃO salva histórico local, cookies ou cache — mas NÃO dá anonimato na internet (ISP ainda vê)
  • HTTPS = HTTP + TLS/SSL → cadeado no navegador = conexão criptografada. Não garante que o site é confiável, garante que a comunicação é segura
  • Favoritos/Bookmarks: Ctrl+D para salvar. Gerenciador: Ctrl+Shift+O
  • Extensões maliciosas: podem capturar dados — instalar apenas de lojas oficiais

Atalhos que caem na prova

Ctrl+T = Nova aba  |  Ctrl+W = Fechar aba  |  Ctrl+Shift+T = Reabrir aba fechada

Ctrl+L ou F6 = Selecionar barra de endereço  |  Ctrl+F = Buscar na página

F5 = Atualizar  |  Ctrl+F5 = Atualizar sem cache  |  F11 = Tela cheia

Cuidado na prova

  • "Navegação privativa garante anonimato na internet" — ERRADO, só não salva dados localmente
  • "HTTPS garante que o site é confiável" — ERRADO, garante apenas criptografia da conexão
  • "Cookies são vírus" — ERRADO, são arquivos de texto com dados de preferência
Webmail e Protocolos de E-mailCobrado▶

Conceitos Rápidos

  • Webmail: acesso ao e-mail pelo navegador (Gmail, Outlook.com). Não precisa instalar nada
  • SMTP (porta 587/465): protocolo para enviar e-mails. Lembrar: SMTP = Saída
  • POP3 (porta 110/995): baixa e-mails para o PC e apaga do servidor (por padrão). Acesso offline
  • IMAP (porta 143/993): sincroniza e-mails com o servidor — e-mail fica no servidor. Ideal para acessar de vários dispositivos
  • CC (cópia): todos veem os destinatários. CCO/BCC (cópia oculta): destinatários ocultos — ninguém vê quem está em CCO

Macete para lembrar protocolos

📤 SMTP = "Seu Mail Tá Partindo" (envio)
📥 POP3 = "Puxa e Ocupa o PC" (baixa e remove do servidor)
🔄 IMAP = "Internet Mail Acesso Permanente" (sincroniza, fica no servidor)

Ferramentas de ProdutividadeCobrado▶

Conceitos Rápidos

  • Microsoft Office: Word (.docx), Excel (.xlsx), PowerPoint (.pptx). Versão online: Office 365/Microsoft 365
  • Google Workspace: Docs, Sheets, Slides — 100% online, colaboração em tempo real, salva no Google Drive
  • LibreOffice: alternativa gratuita/open source — Writer, Calc, Impress. Formato nativo: ODF (.odt, .ods, .odp)
  • Computação em nuvem: armazenamento e processamento remoto. Ex.: Google Drive, OneDrive, Dropbox. Modelos: SaaS (software), PaaS (plataforma), IaaS (infraestrutura)
  • Colaboração em tempo real: vários usuários editam mesmo documento simultaneamente (Google Docs, Office 365)

Equivalências para lembrar

📝 Word = Docs = Writer  |  📊 Excel = Sheets = Calc  |  📽️ PowerPoint = Slides = Impress

☁️ SaaS = você usa o software (Gmail) | PaaS = você desenvolve (Heroku) | IaaS = você monta o servidor (AWS EC2)

3. Noções de Segurança da Informação
Responsabilidades, malware, phishing, aplicativos de segurança, assinatura e certificação digital
Edital §3▶
3.1 Responsabilidades e Deveres dos Usuários de TIBase▶

Conceitos Rápidos

  • Tríade CID: Confidencialidade (só autorizado vê) + Integridade (dado não adulterado) + Disponibilidade (sempre acessível)
  • Autenticidade: garantia de que o remetente é quem diz ser
  • Não-repúdio (irretratabilidade): quem enviou não pode negar que enviou
  • Política de Senhas: mínimo 8-12 caracteres, maiúsculas + minúsculas + números + especiais. Trocar periodicamente. NÃO reutilizar
  • Menor privilégio: cada usuário só acessa o necessário para sua função
  • Backup: completo (tudo), incremental (só o que mudou desde o último backup), diferencial (tudo desde o último completo)

Macete CID + exemplos

🔐 Confidencialidade = senha no arquivo | 🔏 Integridade = hash MD5 do download | 🟢 Disponibilidade = servidor redundante 24/7

📦 Backup: Completo (seg) → Incremental (ter=Δter, qua=Δqua) → se der problema na qua, precisa do completo + Δter + Δqua

📦 Backup: Completo (seg) → Diferencial (ter=Δseg-ter, qua=Δseg-qua) → se der problema na qua, precisa do completo + Δseg-qua apenas

3.2 Malware: Vírus, Worms, Trojans, Spyware, Ransomware e maisAltíssima incidência▶

Conceitos Rápidos

  • Vírus: precisa de um hospedeiro (arquivo) e da execução pelo usuário para se propagar. Ex.: arquivo .exe infectado
  • Worm: auto-replicável, se espalha pela rede sozinho, sem precisar de hospedeiro ou ação do usuário. Consome banda
  • Trojan (Cavalo de Troia): parece programa legítimo, mas carrega código malicioso. NÃO se replica. Ex.: jogo gratuito com backdoor
  • Spyware: espiona o usuário — coleta dados sem consentimento. Subtipo: Keylogger (captura teclado), Screenlogger (captura tela)
  • Ransomware: sequestra dados, criptografa e exige resgate (pagamento). Ex.: WannaCry. Melhor defesa: backup offline atualizado
  • Backdoor: porta dos fundos — acesso remoto não autorizado sem o conhecimento do usuário
  • Zero-day exploit: exploração de vulnerabilidade desconhecida pelo fabricante (sem patch disponível)
  • Rootkit: esconde a presença de malware no sistema, altera o SO para se camuflar
  • Bot/Botnet: computador infectado controlado remotamente. Rede de bots = botnet (usada para DDoS)

Tabela Rápida para Memorizar

🦠 Vírus = precisa de hospedeiro + ação do usuário
🐛 Worm = autônomo, rede, sem hospedeiro
🐴 Trojan = disfarçado, não se replica
👁️ Spyware = espiona silenciosamente
💰 Ransomware = criptografa + pede resgate
🚪 Backdoor = porta dos fundos
⏰ Zero-day = falha desconhecida, sem correção

Cuidado na prova

  • "Worm precisa de ação do usuário para se propagar" — ERRADO, worm se propaga sozinho
  • "Trojan se auto-replica como vírus" — ERRADO, trojan NÃO se replica
  • "Vírus se propaga pela rede sem interação do usuário" — ERRADO, isso é worm
  • "Ransomware apaga dados" — ERRADO, criptografa (não apaga)
3.3 Phishing, Vishing e Engenharia SocialAlta incidência▶

Conceitos Rápidos

  • Engenharia Social: manipulação psicológica para obter informações. Não usa técnica computacional — usa confiança humana
  • Phishing: e-mail/site falso imitando entidade confiável (banco, correios). Objetivo: roubar dados (login, cartão)
  • Spear Phishing: phishing direcionado a pessoa ou organização específica (personalizado)
  • Vishing: phishing por voz (telefone). Ex.: ligação falsa do banco pedindo senha
  • Smishing: phishing por SMS. Ex.: "Sua encomenda parou. Clique aqui"
  • Pharming: redireciona o DNS — mesmo digitando URL correta, vai para site falso
  • Pretexting: criminoso cria cenário falso (pretexto) para obter informação. Ex.: fingir ser do suporte técnico

Macete "PVSPP"

📧 Phishing = e-mail falso
📞 Vishing = voz (telefone)
📱 Smishing = SMS
🌐 Pharming = DNS envenenado
🎭 Pretexting = fingir ser outra pessoa

3.4 Aplicativos para SegurançaCobrado▶

Conceitos Rápidos

  • Antivírus: detecta malware por assinatura (banco de dados conhecido) e heurística (comportamento suspeito)
  • EDR (Endpoint Detection and Response): evolução do antivírus — monitora continuamente o endpoint, detecta ameaças avançadas, permite resposta automatizada. Foco em detecção + resposta
  • Firewall: filtra pacotes de rede — controla entrada e saída de dados. Pode ser hardware ou software. NÃO detecta vírus dentro de arquivos
  • Anti-spyware: detecta e remove spyware/adware específicos
  • Gerenciador de senhas: armazena senhas criptografadas — você só lembra 1 senha mestra (ex.: KeePass, Bitwarden, 1Password)
  • MFA (Autenticação Multifator): algo que sabe (senha) + algo que tem (token/celular) + algo que é (biometria)

Diferença-chave: Antivírus vs EDR vs Firewall

🛡️ Antivírus = "porteiro que verifica identidades" (assinatura de malware)
🔍 EDR = "câmera + alarme + resposta" (monitora comportamento contínuo)
🧱 Firewall = "muro com portão" (controla tráfego de rede, não analisa conteúdo de arquivos)

Cuidado na prova

  • "Firewall detecta vírus em anexos de e-mail" — ERRADO, quem faz isso é antivírus/EDR
  • "EDR é a mesma coisa que antivírus" — ERRADO, EDR é mais completo (detecção + resposta + monitoramento contínuo)
3.5 Assinatura e Certificação DigitalAlta incidência▶

Conceitos Rápidos

  • Criptografia simétrica: mesma chave para cifrar e decifrar. Rápida. Ex.: AES, DES. Problema: como compartilhar a chave?
  • Criptografia assimétrica: par de chaves — pública (todos têm) e privada (só o dono). Ex.: RSA. Cifra com pública → decifra com privada
  • Hash: função que gera um resumo único de tamanho fixo. Ex.: SHA-256, MD5. Qualquer alteração = hash diferente → garante integridade
  • Assinatura digital: assinar = cifrar o hash com a chave privada do remetente. Verificar = decifrar com a chave pública. Garante: autenticidade + integridade + não-repúdio
  • Certificado digital: documento eletrônico que vincula uma chave pública a uma identidade. Emitido por AC (Autoridade Certificadora)
  • ICP-Brasil: infraestrutura brasileira de chaves públicas. AC-Raiz = ITI. Hierarquia: AC-Raiz → ACs → ARs
  • Certificado A1: armazenado no computador (software), validade 1 ano. A3: em token/smartcard (hardware), validade até 5 anos

Fluxo da Assinatura Digital

1️⃣ João calcula o hash do documento
2️⃣ João cifra o hash com sua chave privada → essa é a assinatura
3️⃣ Maria recebe o documento + assinatura
4️⃣ Maria decifra a assinatura com a chave pública de João → obtém o hash original
5️⃣ Maria calcula o hash do documento recebido → se bater = autêntico e íntegro ✅

🔑 Lembrar: Privada assina, Pública verifica | Pública cifra, Privada decifra

Cuidado na prova

  • "Assinatura digital garante confidencialidade" — ERRADO, garante autenticidade, integridade e não-repúdio (quem garante confidencialidade é a criptografia)
  • "Certificado digital é emitido pelo usuário" — ERRADO, emitido pela AC (Autoridade Certificadora)
  • "A chave pública deve ser mantida em segredo" — ERRADO, a pública é distribuída; a privada é secreta

4. Noções de Bancos de Dados
Conceitos, dados estruturados/não estruturados, chaves e relacionamentos
Edital §4▶
4.1 Conceitos Básicos e CaracterísticasBase▶

Conceitos Rápidos

  • Banco de Dados (BD): coleção organizada de dados inter-relacionados. Ex.: cadastro de clientes com nome, CPF, endereço
  • SGBD (Sistema Gerenciador de BD): software que gerencia o BD. Ex.: MySQL, PostgreSQL, Oracle, SQL Server, MongoDB
  • SQL: linguagem padrão para consultar/manipular BD relacional. Comandos: SELECT, INSERT, UPDATE, DELETE
  • Tabela (Relação): estrutura com linhas (registros/tuplas) e colunas (atributos/campos)
  • Propriedades ACID: Atomicidade (tudo ou nada), Consistência (regras mantidas), Isolamento (transações independentes), Durabilidade (dados persistem)

Exemplo Visual

Tabela CLIENTES:
| ID | Nome | CPF | Cidade |
| 1 | Maria | 111.222.333-44 | Brasília |
| 2 | João | 555.666.777-88 | SP |
→ Cada linha = 1 registro (tupla). Cada coluna = 1 atributo (campo)

4.2 Dados Estruturados e Não EstruturadosCobrado▶

Conceitos Rápidos

  • Estruturados: organizados em tabelas com schema fixo. Ex.: planilha Excel, tabela SQL. Fácil de buscar e filtrar
  • Não estruturados: sem formato definido. Ex.: vídeos, imagens, PDFs, áudios, posts em redes sociais. ~80% dos dados mundiais
  • Semiestruturados: possuem alguma organização mas sem schema rígido. Ex.: JSON, XML, e-mails (tem campo, assunto, corpo)
  • BD Relacional: dados estruturados em tabelas (SQL). BD NoSQL: dados não/semi-estruturados (MongoDB, Cassandra)

Macete para lembrar

📊 Estruturado = "cabe numa planilha" (linhas e colunas definidas)
📷 Não estruturado = "não cabe numa planilha" (fotos, vídeos, textos livres)
📋 Semiestruturado = "tem etiquetas mas não é planilha" (JSON, XML)

4.3 Chaves e RelacionamentosEssencial▶

Conceitos Rápidos

  • Chave Primária (PK): identifica unicamente cada registro na tabela. Não aceita NULL nem duplicatas. Ex.: CPF, ID
  • Chave Estrangeira (FK): campo que referencia a PK de outra tabela — cria o relacionamento. Ex.: cliente_id na tabela Pedidos
  • Chave Candidata: qualquer coluna que poderia ser PK (única). A PK é escolhida entre as candidatas
  • 1:1 (um para um): 1 pessoa → 1 CPF. 1:N (um para muitos): 1 cliente → N pedidos. N:N (muitos para muitos): alunos ↔ disciplinas (precisa tabela intermediária)
  • Integridade referencial: FK deve referenciar uma PK existente — não pode ter FK "solta" apontando para registro inexistente

Exemplo de Relacionamento

Tabela CLIENTES: ID (PK), Nome
Tabela PEDIDOS: PedidoID (PK), Data, ClienteID (FK → CLIENTES.ID)
→ 1 Cliente tem N Pedidos = relacionamento 1:N

Cuidado na prova

  • "Chave primária pode ter valores duplicados" — ERRADO, deve ser única
  • "Chave estrangeira identifica unicamente o registro" — ERRADO, quem faz isso é a primária
  • "Relacionamento N:N é implementado diretamente" — ERRADO, precisa de tabela intermediária

5. Noções de Redes de Computadores
LAN/MAN/WAN, Internet/Intranet, TCP/IP, NAT, VPN, RDP
Edital §5▶
5.1 Tipos de Rede: LAN, MAN e WANCobrado▶

Conceitos Rápidos

  • LAN (Local Area Network): rede local — escritório, casa, escola. Alcance: até ~1 km. Alta velocidade, baixo custo. Ex.: rede Wi-Fi da sua casa
  • MAN (Metropolitan Area Network): rede metropolitana — interliga várias LANs numa cidade. Ex.: rede da prefeitura conectando vários prédios públicos
  • WAN (Wide Area Network): rede de longa distância — conecta cidades, países, continentes. Ex.: a própria Internet é a maior WAN
  • PAN (Personal Area Network): rede pessoal — Bluetooth, NFC. Alcance: ~10 m. Ex.: fone sem fio
  • WLAN: LAN sem fio (Wi-Fi). Padrão IEEE 802.11. Ethernet = LAN cabeada, padrão IEEE 802.3

Macete do tamanho crescente

👤 PAN (pessoa) → 🏠 LAN (local) → 🏙️ MAN (metrópole) → 🌍 WAN (mundo)

Dica: LANhouse = local | MANhattan = cidade | WANderlust = viajar pelo mundo

5.2 Internet e IntranetMuito cobrado▶

Conceitos Rápidos

  • Internet: rede pública mundial — qualquer pessoa acessa. Usa TCP/IP
  • Intranet: rede privada da organização — usa mesmos protocolos da Internet (TCP/IP, HTTP) mas acesso restrito a funcionários
  • Extranet: extensão da Intranet para parceiros externos autorizados (fornecedores, clientes). Ex.: portal do fornecedor
  • DNS (Domain Name System): traduz nomes de domínio para IPs. Ex.: google.com → 142.250.79.14. Funciona como a "agenda telefônica" da Internet
  • DHCP: atribui IPs automaticamente aos dispositivos na rede. Sem DHCP = configurar IP manualmente
  • URL: endereço completo. Ex.: https://www.exemplo.com.br/pagina → protocolo + domínio + caminho

Diferença visual

🌐 Internet = aberta para todos (rede pública)
🏢 Intranet = só para funcionários (rede privada, mesma tecnologia)
🤝 Extranet = intranet + parceiros autorizados de fora

Cuidado na prova

  • "Intranet não usa protocolo TCP/IP" — ERRADO, usa os mesmos protocolos da Internet
  • "Internet e Intranet são a mesma coisa" — ERRADO, Intranet é privada
  • "Extranet é acessível por qualquer pessoa" — ERRADO, apenas parceiros autorizados
5.3 Arquitetura TCP/IP e NATEssencial▶

Conceitos Rápidos

  • Modelo TCP/IP — 4 camadas (de baixo para cima):
    1️⃣ Acesso à Rede (enlace/física) → cabos, Wi-Fi, Ethernet
    2️⃣ Internet → IP, ICMP, ARP → endereçamento e roteamento
    3️⃣ Transporte → TCP (confiável, com conexão) e UDP (rápido, sem conexão)
    4️⃣ Aplicação → HTTP, HTTPS, FTP, SMTP, DNS, DHCP
  • IP (Internet Protocol): endereço lógico de cada dispositivo. IPv4: 32 bits (ex.: 192.168.1.1). IPv6: 128 bits (ex.: 2001:0db8::1)
  • TCP: orientado a conexão, confiável, garante entrega na ordem (handshake SYN-SYN/ACK-ACK). Usado por: HTTP, FTP, SMTP, SSH
  • UDP: sem conexão, mais rápido, não garante entrega. Usado por: DNS, streaming, VoIP, jogos online
  • NAT (Network Address Translation): traduz IPs privados (da rede interna) para um IP público (da internet). Permite que vários dispositivos compartilhem 1 IP público
  • IP privado: 10.x.x.x, 172.16-31.x.x, 192.168.x.x — NÃO roteável na Internet

Macete para protocolos e portas

🔵 HTTP = 80 | HTTPS = 443 | FTP = 20/21 | SSH = 22 | DNS = 53 | SMTP = 587

🟢 TCP = "Tem Certeza, Parceiro?" (confiável, confirma tudo)
🟡 UDP = "Ui, Danou-se, Passou!" (manda e não verifica)

🏠 NAT = "tradutor de endereços" — sua casa tem 5 dispositivos com IPs internos → o roteador tem 1 IP público → NAT traduz

Cuidado na prova

  • "UDP é confiável e garante entrega" — ERRADO, isso é TCP
  • "IPv4 usa 128 bits" — ERRADO, IPv4 = 32 bits; IPv6 = 128 bits
  • "NAT criptografa os dados" — ERRADO, NAT apenas traduz endereços IP
5.4 Acesso Remoto: VPN e RDPCobrado▶

Conceitos Rápidos

  • VPN (Virtual Private Network): cria um túnel criptografado pela Internet pública, simulando uma rede privada. Garante confidencialidade e integridade
  • Uso: funcionário em casa acessa a rede da empresa de forma segura pela Internet
  • Protocolos VPN: IPSec (camada rede), OpenVPN (SSL/TLS), L2TP, WireGuard
  • RDP (Remote Desktop Protocol): protocolo da Microsoft para acesso remoto à área de trabalho. Porta padrão: 3389. Permite controlar outro PC como se estivesse na frente dele
  • Diferença: VPN = acessar a rede da empresa. RDP = controlar a tela de outro computador
  • Outros: SSH (porta 22) = acesso remoto via linha de comando (terminal); TeamViewer/AnyDesk = acesso remoto gráfico

Analogia para lembrar

🔒 VPN = "túnel secreto" pela internet → você entra na rede da empresa como se estivesse lá
🖥️ RDP = "controle remoto da TV" → você vê e controla a tela do outro PC
⌨️ SSH = "telefone para o servidor" → só texto/comandos, sem tela gráfica

6. Noções de Aprendizado de Máquina
Mineração de dados, Big Data e IA Generativa
Edital §6▶
6.1 Mineração de Dados (Data Mining)Cobrado▶

Conceitos Rápidos

  • Mineração de dados: processo de descobrir padrões, correlações e anomalias em grandes volumes de dados
  • Objetivo: transformar dados brutos em informação útil para tomada de decisão
  • Técnicas comuns: classificação (categorizar dados), clustering (agrupar sem rótulos), associação (encontrar relações — "quem compra X também compra Y"), regressão (prever valor numérico)
  • Etapas (KDD): seleção → pré-processamento → transformação → mineração → interpretação/avaliação
  • Machine Learning (ML): subárea da IA que usa algoritmos que aprendem com os dados sem serem explicitamente programados
  • Tipos de ML: Supervisionado (dados rotulados — ex.: spam/não spam), Não supervisionado (sem rótulos — clustering), Por reforço (tentativa e erro com recompensas)

Exemplos práticos

🛒 Associação: "Clientes que compram fraldas também compram cerveja" (supermercado)
📧 Classificação: Gmail separando e-mail em "spam" ou "não spam"
👥 Clustering: agrupar clientes por perfil de consumo (sem categorias prévias)
📈 Regressão: prever o preço de um imóvel com base em área, localização

6.2 Big Data: Conceito, Premissas e AplicaçãoMuito cobrado▶

Conceitos Rápidos

  • Big Data: conjuntos de dados tão grandes e complexos que ferramentas tradicionais de BD não conseguem processar
  • 5 Vs do Big Data:
    📦 Volume: quantidade massiva de dados (petabytes, exabytes)
    ⚡ Velocidade: dados gerados e processados em tempo real (ou quase)
    🔀 Variedade: dados de formatos diversos (texto, imagem, vídeo, sensor)
    ✅ Veracidade: confiabilidade e qualidade dos dados
    💎 Valor: capacidade de extrair insights úteis dos dados
  • Tecnologias: Hadoop (processamento distribuído), Spark (processamento em memória, mais rápido), NoSQL (BDs flexíveis)
  • Aplicações: análise de redes sociais, detecção de fraude bancária, medicina personalizada, previsão de demanda

Macete dos 5 Vs

Pense no fluxo de água:
📦 Volume = quanta água (dado) existe
⚡ Velocidade = quão rápido a água flui
🔀 Variedade = água doce, salgada, gelo, vapor (formatos diferentes)
✅ Veracidade = a água está limpa? (dado confiável?)
💎 Valor = consigo gerar energia com essa água? (insight útil?)

Cuidado na prova

  • "Big Data são apenas dados em grande volume" — ERRADO, envolve os 5 Vs (não só volume)
  • "Big Data pode ser processado com ferramentas tradicionais de BD" — ERRADO, requer tecnologias específicas
6.3 IA Generativa: Principais CaracterísticasNovo no edital▶

Conceitos Rápidos

  • IA Generativa: modelos de IA capazes de criar conteúdo novo (texto, imagem, código, áudio, vídeo) a partir de padrões aprendidos
  • Exemplos: ChatGPT (texto), DALL-E/Midjourney (imagem), GitHub Copilot (código), Suno (música)
  • LLM (Large Language Model): modelo treinado com bilhões de textos para gerar linguagem natural. Ex.: GPT, LLaMA, Gemini
  • Prompt: instrução/pergunta que o usuário fornece ao modelo. Qualidade do prompt → qualidade da resposta
  • Alucinação: quando o modelo gera informação falsa com aparência de verdadeira — risco principal
  • Deep Learning: redes neurais profundas (muitas camadas) — base da IA generativa. Subtipo de Machine Learning
  • Deepfake: manipulação de vídeo/áudio por IA para criar conteúdo falso hiper-realista (rostos, vozes)
  • Riscos: viés algorítmico, desinformação, violação de direitos autorais, deepfakes

Hierarquia para lembrar

🧠 IA (Inteligência Artificial) — campo amplo
  ↳ 📊 Machine Learning — aprender com dados
    ↳ 🔗 Deep Learning — redes neurais profundas
      ↳ ✨ IA Generativa — criar conteúdo novo (ChatGPT, DALL-E)

Cuidado na prova

  • "IA generativa sempre produz informação verdadeira" — ERRADO, pode alucinar
  • "Deep Learning é sinônimo de Machine Learning" — ERRADO, DL é uma subcategoria de ML
  • "Deepfake só manipula vídeo" — ERRADO, também manipula áudio

7.1 Recuperação de Arquivos ApagadosEssencial▶

Conceitos Rápidos

  • Quando um arquivo é "apagado", o SO marca o espaço como disponível mas os dados permanecem no disco até serem sobrescritos
  • Data Carving (file carving): técnica de recuperar arquivos sem usar metadados do sistema de arquivos — busca por assinaturas de arquivo (magic numbers/headers). Ex.: JPEG começa com FF D8 FF
  • Tabela de alocação (FAT/MFT): ao deletar, a referência na tabela é removida, mas os clusters com dados permanecem
  • NTFS – MFT ($MFT): Master File Table registra metadados de cada arquivo. Arquivo deletado = flag marcada, mas entrada mantida
  • Lixeira do Windows: move arquivo para $Recycle.Bin — ainda recuperável facilmente. Após esvaziar = carving necessário
  • SSD com TRIM: ao deletar, o SSD pode zerar os blocos imediatamente → recuperação muito mais difícil ou impossível
  • Ferramentas: Autopsy, FTK, EnCase, Recuva, PhotoRec

Analogia para lembrar

📖 Deletar arquivo = arrancar o índice de um livro — as páginas (dados) ainda existem, mas você perdeu a referência
🔍 Carving = folhear todas as páginas procurando pelo conteúdo sem usar o índice
⚡ SSD + TRIM = não só arrancou o índice, como rasgou as páginas (dados apagados de verdade)

7.2 Identificação, Isolamento, Preservação e Coleta de Vestígio CibernéticoEssencial▶

Conceitos Rápidos

  • Vestígio cibernético: qualquer dado digital que possa servir como evidência — arquivos, logs, registros de rede, metadados, e-mails
  • Ordem de volatilidade (coletar do mais volátil para o menos):
    1️⃣ Registradores/Cache da CPU
    2️⃣ Memória RAM
    3️⃣ Dados de rede (tabela ARP, conexões ativas)
    4️⃣ Dados em disco (arquivos, logs)
    5️⃣ Logs remotos/backups
  • Imagem forense (bit-a-bit): cópia exata do disco original — nunca trabalhar no original. Ferramentas: dd, FTK Imager, EnCase
  • Hash de verificação: calcular MD5/SHA-256 do original e da cópia — se baterem, a cópia é íntegra
  • Write blocker: dispositivo que impede qualquer escrita no disco original durante a cópia — garante que o perito não altera a evidência
  • Princípio: nunca alterar a evidência original — toda análise é feita na cópia forense

Sequência prática em cena de crime digital

1️⃣ Identificar: localizar dispositivos e mídias relevantes (PC, celular, pendrive, nuvem)
2️⃣ Isolar: desconectar da rede (evitar acesso/alteração remota). NÃO desligar antes de capturar RAM
3️⃣ Preservar: capturar RAM (volátil) → usar write blocker → gerar imagem bit-a-bit → calcular hash
4️⃣ Coletar: documentar tudo (fotos, anotações), embalar fisicamente, etiquetar, registrar cadeia de custódia

Cuidado na prova

  • "A análise deve ser feita diretamente no disco original" — ERRADO, sempre na cópia forense
  • "RAM não é relevante para análise forense" — ERRADO, pode conter senhas, processos e chaves de criptografia
  • "Desligar o computador é a primeira coisa a fazer" — ERRADO, primeiro capturar dados voláteis (RAM)
7.3 Cadeia de Custódia DigitalAlta incidência▶

Conceitos Rápidos

  • Cadeia de custódia: documentação completa do histórico da evidência — quem coletou, quando, onde, como foi armazenada, quem acessou
  • Garante a admissibilidade da prova em juízo — se a cadeia for quebrada, a prova pode ser questionada
  • Hash é a base da integridade digital: hash antes → análise → hash depois → se bater = não houve alteração
  • Etapas (art. 158-B CPP): reconhecimento → isolamento → fixação → coleta → acondicionamento → transporte → recebimento → processamento → armazenamento → descarte
  • Tudo documentado com data, hora, responsável e procedimento realizado
  • Evidência digital é frágil: pode ser alterada facilmente → por isso hash + write blocker são essenciais

Analogia

📦 Cadeia de custódia digital = "rastreamento de encomenda" — você sabe exatamente onde a evidência esteve em cada momento, quem tocou nela, e pode provar que ninguém adulterou

7.4 Log de Eventos do WindowsCobrado▶

Conceitos Rápidos

  • Visualizador de Eventos (eventvwr.msc): ferramenta nativa do Windows para consultar logs de eventos do sistema
  • Logs principais:
    📋 Application (Aplicativo): eventos de programas (erros, avisos do Word, SQL Server, etc.)
    ⚙️ System (Sistema): eventos do SO e drivers (falha de hardware, inicialização)
    🔐 Security (Segurança): eventos de autenticação — logon, logoff, acesso a recursos, falhas de login (mais importante para forense)
    📦 Setup (Instalação): eventos de instalação de componentes/atualizações
  • Event IDs importantes:
    4624 = logon bem-sucedido
    4625 = falha de logon
    4634 = logoff
    4720 = conta de usuário criada
    4726 = conta de usuário deletada
    4648 = logon com credenciais explícitas
  • Formato do arquivo de log: .evtx (Windows Vista+). Armazenados em C:\Windows\System32\winevt\Logs\
  • Logs podem ser exportados, filtrados por data/ID/fonte e encaminhados para servidor centralizado (SIEM)

Cenário forense prático

🕵️ Investigar acesso indevido:
1️⃣ Abrir eventvwr.msc → Security
2️⃣ Filtrar por Event ID 4624 (logons bem-sucedidos) → ver horário e conta utilizada
3️⃣ Filtrar por Event ID 4625 (falhas) → tentativas de senha errada = possível brute force
4️⃣ Correlacionar com horários suspeitos → evidência de acesso não autorizado

📌 IDs para decorar: 4624 = entrou ✅ | 4625 = não entrou ❌ | 4720 = criou conta 👤

Cuidado na prova

  • "Logs de segurança registram apenas eventos de sistema" — ERRADO, registram autenticação e acesso
  • "Logs do Windows não podem ser exportados" — ERRADO, podem ser exportados e filtrados
  • "Event ID 4624 indica falha de logon" — ERRADO, 4624 = sucesso; 4625 = falha
